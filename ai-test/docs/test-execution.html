AI Test — Execution Design

What happens when you run npm run ai-test:suite. Offline LLM evaluation only — no browser, no Playwright, no auto-heal.

Export to PDF: open this file in a browser → Ctrl+P (or Cmd+P) → Save as PDF.

Big picture (5 steps)

1

Start

You run npm run ai-test:suite. It loads .env and checks LM Studio settings (LMSTUDIO_BASE_URL, LMSTUDIO_MODEL).

↓
2

Find cases

Lists folders under ai-test/inputs/ that contain results.json. Optional: --case locator-typo runs one case only.

↓
3

For each case → ask the LLM

Read saved failure data from disk, send a triage prompt to LM Studio, get back groups (category, summary, which tests are duplicates).

↓
4

Score (if ground truth exists)

Compare LLM output to groundtruth.json. Case passes if triage score ≥ 80% (default). Otherwise fail.

↓
5

Write reports

Latest report under ai-reports/ai-test-suite.*. History CSVs updated so you can compare models over time.

One case — data flow

inputs/<case>/results.json → Parse failures → Triage LLM → Score vs groundtruth → Report + CSV history

Attachments in the same folder (error-context.md, page-html.html, page-css.css) are read when building the failure payload. They are not fetched from a live test run.

What each case folder contains

Inputs (on disk before you run)
  • results.json — saved Playwright JSON report
  • error-context.md — optional snapshot
  • page-html.html, page-css.css — optional page evidence
  • groundtruth.json — expected triage for scoring
Outputs (after each run)
  • ai-reports/ai-test-suite.md — human summary
  • ai-reports/ai-test-suite.json — full JSON
  • ai-reports/ai-test-suite/<case>/triage.json — LLM result per case
  • ai-reports/ai-test-history/*.csv — model comparison over time

Inside step 3 — one LLM call per case

What Where
Load failure list from results.json case-report.ts
Load testing standards (markdown policy files) triage-eval.ts
Build prompt + call LM Studio scripts/lib/llm-batch.ts
Normalize groups / categories scripts/lib/failure-triage.ts

All failures in one case are sent together in a single triage request (e.g. 18 duplicate checkout tests → one grouped answer).

Scoring (step 4)

Only runs when groundtruth.json exists. Weighted score:

triageScore = 35% root cause + 25% grouping + 25% category + 15% detail fields

Default pass threshold: 0.8 (--min-score to change). A case with perfect grouping, category, and detail but no root-cause text match caps at 65% → marked fail.

What ai-test does not do

Not part of this command Playwright / browser tests · fix-plan LLM · apply patches · CI pipeline · re-run tests

Fixtures are copied manually from a real Playwright run once. After that, evaluation replays files on disk only.

Commands

npm run ai-test:suite All cases
npm run ai-test:suite -- --case locator-typo Single case
npm run ai-test:suite -- --open Open markdown report when done
npm run ai-test:suite -- --min-score 0.65 Lower pass bar
